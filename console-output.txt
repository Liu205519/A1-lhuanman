================================================================================
 PART 1 - MODELLING A HEALTH PROFESSIONAL
================================================================================
HealthProfessional is abstract, so the compiler rejects
    new HealthProfessional("2001", "Dr Nobody")
and a professional can only ever be created as a real type.

The class offers two ways of constructing an object:
    (id, name)                   -> works the default Monday to Friday week
    (id, name, availableDays)    -> works exactly the days supplied

Every field is private and set once by the constructor, and the
constructor validates each value, so an object can never exist in an
invalid state. The getters return copies of the mutable data.

Details of one professional, built by HealthProfessional.toString()
and the toString() of each type it inherits from:
  | ID              | 2001 |
  | Name            | Dr Alice Nguyen |
  | Type            | General Practitioner |
  | Available days  | Monday, Wednesday, Friday |
  | Duties          | Diagnoses and treats common health problems and refers patients on. |
  | Registration    | MED10023 |
  | Consult room    | Room 3 |
  | Experience      | 12 years |

  The constructor refuses to build an invalid object
  --------------------------------------------------------------------------------
  rejected ID "AB12"       -> ID must be numbers only, but was: "AB12"
  rejected a blank name    -> Name is required.
  rejected an empty week   -> At least one available day is required.
  rejected a repeated day  -> Monday is listed more than once.
  rejected a bad mobile    -> Mobile number must contain 10 digits, but was: "0412-ABC"
  rejected minute 75       -> Minute must be between 0 and 59, but was: 75

 PARTS 2 AND 3 - SPECIALISING AND WORKING WITH HEALTH PROFESSIONALS
================================================================================
Hierarchy:
    HealthProfessional (abstract)
        +-- Doctor (abstract) -- adds prescribing and registration
        |     +-- GeneralPractitioner
        |     +-- Specialist
        |     +-- Surgeon
        +-- Nurse
        +-- Dietitian

Each type inherits the shared data and adds only what makes it
different. Each type overrides getProfessionalType(), getDuties()
and provideService(), so it responds in its own way.

  Nurse Tom Becker checks the observations of Chloe Martin on Ward 2A.
  [Dietitian]
  Ms Hannah Price reviews the diet of Chloe Martin for Diabetes and weight management.

  Doctor-only behaviour, through the Doctor type
  --------------------------------------------------------------------------------
  Only doctor types can prescribe, so they are processed as Doctor
  objects. prescribe() is written once in Doctor and inherited by every
  doctor type, so one line per doctor is produced:

  Dr Alice Nguyen (registration MED10023) prescribes Amoxicillin to Chloe Martin.
  Dr Ben Carter (registration MED10047) prescribes Amoxicillin to Chloe Martin.
  Dr Priya Sharma (registration MED10052) prescribes Amoxicillin to Chloe Martin.
  Dr Marcus Lee (registration MED20015) prescribes Amoxicillin to Chloe Martin.
  Dr Sofia Rossi (registration MED20031) prescribes Amoxicillin to Chloe Martin.
  Dr Henry Okafor (registration MED30008) prescribes Amoxicillin to Chloe Martin.

  Behaviour that belongs to one type only
  --------------------------------------------------------------------------------
  Each of these methods exists on one class only, not on
  HealthProfessional, so the type that owns it must be used.

  Dr Marcus Lee orders a blood culture for Daniel Kim through St Vincent's Hospital.
  Dr Henry Okafor performs a knee arthroscopy on Daniel Kim in Theatre 2.
  Nurse Grace Miller takes a blood sample from Daniel Kim on Ward 4B.
  Ms Hannah Price creates a meal plan for Daniel Kim focused on Diabetes and weight management.

  The surgeon's private operation count is now 1, changed only through
  performOperation(), never by touching a field.

  Adding a sixth type would mean adding one subclass, and none of the
  loops in this demonstration would have to change.

================================================================================
 PART 4 - MODELLING AN APPOINTMENT
================================================================================
An appointment holds a Patient, a HealthProfessional and a TimeSlot.
All three are required, so the constructor refuses to build an
incomplete appointment. The professional is held as a
HealthProfessional, so any of the five types can be booked.

  Appointment at 09:30
    General Practitioner - Dr Alice Nguyen (ID 2001)
    Patient          : Chloe Martin, mobile 0412 345 678
    Health professional details:
      | ID              | 2001 |
      | Name            | Dr Alice Nguyen |
      | Type            | General Practitioner |
      | Available days  | Monday, Wednesday, Friday |
      | Duties          | Diagnoses and treats common health problems and refers patients on. |
      | Registration    | MED10023 |
      | Consult room    | Room 3 |
      | Experience      | 12 years |

  The same appointment class works with a nurse
  --------------------------------------------------------------------------------
  Time  | ID      | Health professional      | Type                        | Patient          | Mobile      
  08:30 | 5001    | Nurse Grace Miller       | Nurse                       | Emma Wilson      | 0434 567 890

  Appointments know how to order themselves
  --------------------------------------------------------------------------------
  Appointment implements Comparable, comparing TimeSlot first, so
  Collections.sort() puts a whole day in time order.

  Before sorting (in the order they were created):
    10:30  Chloe Martin
    08:00  Daniel Kim
    09:30  Emma Wilson
  After Collections.sort():
    08:00  Daniel Kim
    09:30  Emma Wilson
    10:30  Chloe Martin
